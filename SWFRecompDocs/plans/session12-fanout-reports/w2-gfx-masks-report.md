## 1. What shipped

### 1.1 `avm2_display.c` — the AVM2 mask walk (defect D / T7)

`avm2_render_node` now implements Ruffle's `display_object.rs::render_base` +
`container.rs::render_children` mask model on top of the **flat**
single-reference stencil that s11's defect-A work left in `render_webgpu.c`.
Four rules:

1. **Masker suppression** — `if (ext->maskee != NULL) return;`. Ruffle
   `render_base` (`display_object.rs:952`: `options.skip_masks &&
   this.maskee().is_some()`), where `skip_masks` defaults to `true` and is only
   `false` when Ruffle is explicitly drawing the mask. This is one half of every
   "mask painted as content on top of the unclipped maskee" diff in the slice.
2. **`visible` is ignored inside a mask** — Ruffle `container.rs`: *"The
   'visible' flag is ignored for all descendants of a mask."* `visible = false`
   is the normal way to keep a masker off screen; honouring it while writing
   the stencil yields an EMPTY mask, i.e. a blank maskee.
   `g_avm2_drawing_mask` is Ruffle's `commands.drawing_mask()`.
3. **`DisplayObject.mask`** — push the masker's silhouette, draw the node and
   its whole subtree against it, restore. The masker lives elsewhere in the
   tree, so its stencil pass runs under **its own parent's** world matrix
   (`display_world_matrix(ctx, mext->parent)`), never the maskee's — Ruffle
   composes `inv(this.l2g) * m.l2g` onto a stack that already holds `this.l2g`,
   which is the same matrix.
4. **Timeline clip layers** — a child with `clip_depth > 0` is never painted as
   content; it masks the depth range `(depth, clip_depth]`, closing at the first
   later child whose `depth` passes `clip_depth` and again at end of list.
   Mirrors `container.rs::render_children` and the identical range logic the
   *pick* walk has always had (`avm2_display.c:11986-12034`) — that asymmetry
   (the pick walk knows about masks, the paint walk did not) was the whole
   defect.

### 1.2 `avm2_display.c` — `do_set_mask` retires `clip_depth` (the `mask_reapply` key)

Ruffle `DisplayObject::set_mask` is four lines and two of them are
`set_clip_depth(0)`:

```rust
fn set_mask(self, mask: Option<DisplayObject<'gc>>, mc: &Mutation<'gc>) {
    self.set_clip_depth(0);
    self.set_masker(mc, mask, true);
    if let Some(mask) = mask { mask.set_clip_depth(0); mask.set_maskee(mc, Some(self), true); }
}
```

An AS mask assignment **retires any timeline clip range either object was part
of**, so the two mask mechanisms can never both be live on one pair. Our
`do_set_mask` kept the pair symmetric but never touched `clip_depth`.

That is exactly what `avm2/mask_reapply` tests. Its timeline is

```
depth 1  char 2  clipDepth 5  name "mask1"      depth 3  char 4  name "maskee1"
depth 6  char 2  clipDepth 7  name "mask2"      depth 7  char 4  name "maskee2"
```

and its ABC (recovered from the emitted `abc0_methods.c` opcode comments) is

```
maskee1.mask = mask1      // reapplied the right way round
mask2.mask   = maskee2    // reapplied BACKWARDS   <-- the actual test
trace("Masks reapplied")
```

With the walk alone (§1.1) the first pair rendered and the second did not:
`mask2` still carried `clip_depth = 7`, so it was consumed as a timeline masker
while `maskee2` — now a `maskee` — was suppressed as content. One blue patch
instead of two, **832 → 0** outliers once `clip_depth` is cleared. Ruffle's
answer for pair 2 is that `mask2` becomes an ordinary object masked by
`maskee2`; the visible intersection is the same rectangle.

### 1.3 `render_webgpu.c` / `.h` / `renderer.h` — clip save/restore (2 new functions)

`render_webgpu_end_clip` zeroes `mask_ref`, which is right for the `tag.c` loops
(their clip ranges are siblings) but wrong for the AVM2 walk, where a mask can
open **inside** an already-masked subtree. Two new entry points:

```c
u32  render_webgpu_clip_ref(ctx);               // ctx->mask_ref
void render_webgpu_restore_clip(ctx, u32 ref);  // mask_ref = ref; restore_draw_pipeline
```

Restoring costs no geometry replay: the stencil is cleared once per pass, so the
texels the enclosing mask wrote still hold its reference. What it *cannot*
recover is the region where the inner mask overwrote the outer reference
(`Replace`, not `Increment`) — **nesting still does not intersect**, the same
flat-mask limitation `tag.c` has carried since s11 (§6.2).

Both functions are purely additive; **no existing renderer function changed
behaviour**, which is what bounds the blast radius (§3). `renderer.h` gains the
two macros in both arms (`(0u)` / `((void)0)` in the `NO_GRAPHICS` arm);
`avm2_display.c` compiles clean under `-DNO_GRAPHICS` as well as
`-DUSE_WEBGPU -DOFFSCREEN_RENDER`.

## 3. Blast radius — bounded by construction, then measured

The patch is **additive outside the AVM2 render walk**: `render_webgpu.c` gains
two functions and modifies none, `renderer.h` gains two macros, and the only
behavioural edits are inside `avm2_render_node` and `do_set_mask`. So the whole
AVM1 / `tag.c` render path — every timeline mask, every EditText field clip,
every Drawing-API `setMask`, every blend and filter composite — is
**bit-identical by construction**, not by luck. The AVM1 rows of the canary are
the check on that claim (all 13 IDENTICAL); the AVM2 rows are the real exposure
and the two AVM2 mask-adjacent passers held.

The one semantic risk this patch *does* introduce: a masker whose geometry does
not rasterise (an empty Sprite, a Graphics child we do not tessellate) now clips
its maskee **away** instead of leaving it unclipped. That is Ruffle's behaviour,
but it converts "wrong but visible" into "blank" wherever our geometry coverage
is incomplete. No corpus comparison in the canary regressed that way; the wider
AVM2 pixel surface is only sampled here, so an `images=true` CI run is the real
check.

## 4. Refutation: the `masks` / `masks_equal_clipdepth` 1686 residual is NOT a mask defect

The wave-1 board named this the open question for my slice. It is not a mask
mechanism and no B/C/D fix can own it.

`visual/simple_shapes/masks` has **no `DoABC` tag** → it renders through
`tag.c`, so the AVM2 walk cannot reach it; it uses neither `setMask` nor
`scrollRect`, so B and C cannot either. Rendered at HEAD and diffed
pixel-by-pixel against its golden:

```
1686 outlier channels = 776 mismatching pixels
bbox (17,8)-(544,388)            <- the WHOLE stage, not a mask region
dominant pairs:  422 px  actual (255,0,0)    expected (255,255,255)
                 177 px  actual (0,0,0)      expected (255,255,255)
                  43 px  actual (0,0,0)      expected (0,153,255)
                  35 px  actual (0,153,255)  expected (255,255,255)
                  29 px  actual (0,0,0)      expected (255,0,0)
```

Every pair is between two **saturated** palette colours with no intermediate
values anywhere — which is what `quality = "low"` → `MSAA_SAMPLES = 1` (s11's
quality-aware MSAA) guarantees. These are one-pixel slivers along curve
boundaries spread over the entire image: our tessellator and Ruffle's rasteriser
disagree about which side of a sample point an edge falls on.

That is the board's own `hairline_edge_drift` A-INHERENT family, mis-clustered as
`c_small` only because the count is small. **Recommendation: move the `masks`
twins out of the mask cluster; the mask mechanism in those two tests has been
correct since s11 and no mask session should book them again.**

## 5. Defects B and C at HEAD — re-verified, not shipped

### B — AVM1 `setMask` never reaches display-list content: CONFIRMED

`grep -n 'mask_mc\|is_mask\|as_is_mask\|as_masked_by' SWFModernRuntime/src/libswf/tag.c`
still returns **zero hits**. `action.c`'s `setMask` sets `mc->mask_mc` and
`mask_mc->is_mask`; those are consumed only by `actionIterateDrawings` /
`actionIterateMaskedDrawings` (the Drawing-API path,
`tag.c:5264 masked_drawing_render_cb`), `BitmapData.draw`, and hit-testing. So
`setMask` works only when **both** clips carry Drawing-API geometry.

**Two reasons it is not in this patch:**

1. **The s10 fix design has a use-after-free.** s10 §6 proposed
   `struct DisplayObject* as_masked_by` on `DisplayObject`. The display list is
   a **realloc'd array indexed by depth** (`sprite-dl-realloc-rebase`), so a
   stored `DisplayObject*` dangles the moment the list grows. The field must be
   a *depth* plus an owning-list discriminator, or the pairing must be resolved
   at render time from `mc->display_obj`.
2. **The yield re-prices down.** s10 booked "1 flip"
   (`visual/simple_shapes/text_field_mask`). That test is `quality = "low"`, so
   since s11 it renders at 1 MSAA sample and is no longer AA-blocked — but its
   content is **glyph outlines**, and §4 just measured that two rasterisers at
   1 sample still disagree by hundreds of edge pixels on curves. Predict a large
   band move and treat the flip as **uncertain**. Its blast radius is the whole
   AVM1 display loop (three copies), the widest surface in the renderer.

### C — `scrollRect` is a stub in both VMs: CONFIRMED

AVM1: still one of the ten names in `action.c`'s `extra_props[]` — a stored
value with no bounds, scroll or clip effect. AVM2: `has_scroll_rect` / `sr_*`
are stored and already override the object's bounds (`avm2_display.c:725`,
setter at `10250-10279`), and `avm2_render_node` still never reads them —
`avm2/displayobject_scrollrect` sat at `fail 202388` in both canary legs, which
is the control proving I did not touch it.

**Owned by the session-12 `scrollRect` sibling.** Hand them §6.1.

## 6. Arc-sized leftovers, with the next step named

### 6.1 AVM2 `scrollRect` — 2 comparisons, ~20 lines, ready to drop in

`avm2/displayobject_scrollrect` (202388) and `visual/avm2_button_scroll_rect`
(28851). Ruffle `apply_standard_mask_and_scroll` (`display_object.rs:1166`): the
crop is a `w × h` rect at the node's **local origin** — `cur_transform.matrix *
scale(w_px, h_px)`, the translation deliberately *not* applied to it — and the
content is then translated by `(-x_min, -y_min)`. In our walk, right after
`world` is computed:

```c
uint32_t sr_saved = 0; int sr_pushed = 0;
if (ext->has_scroll_rect && g_avm2_drawing_mask == 0) {
    sr_saved = renderer_clip_ref(context);
    renderer_begin_clip_mask(context);
    /* rect (0,0, sr_xmax-sr_xmin, sr_ymax-sr_ymin) twips, under `world` */
    renderer_end_clip_mask(context);
    sr_pushed = 1;
    Mat tr = { 1,0,0,1, -(double)ext->sr_xmin, -(double)ext->sr_ymin };
    world = mat_mul(&world, &tr);
}
```

plus a matching `renderer_restore_clip(context, sr_saved)` beside the existing
`pushed_mask` restore. **Caveat we would inherit from Ruffle:** the scroll
translate is pushed *before* the `DisplayObject.mask` transform, so an object
that is both scrolled and masked conjugates its mask by the translate. Land
scrollRect on unmasked objects first.

### 6.2 Nesting intersection — the one real semantic gap left

`begin_clip_mask` is `Always/Replace` at a fresh reference, so a mask inside a
mask replaces its parent instead of intersecting it, and `restore_clip` cannot
recover the overwritten overlap. `regression/mask_nested_intersect` — built and
validated by s11, generator shipped as
`session11-fanout-reports/w2-masks-r2-mask_nested_intersect.py`, deliberately
**not** in the suite — is the pin test and still fails at 10800. The fix is s11
§6's `Equal/IncrementClamp` write + `Equal/DecrementClamp` clear with a
full-screen decrement draw. It is now worth more than it was: one renderer
change that fixes **both** walks, and `restore_clip` becomes exact instead of
approximate.

## 8. Reproduction notes (three traps worth keeping)

1. **`RecompiledABC/` is generated, not committed.** Deciding "AVM1 path vs AVM2
   path" by looking for `RecompiledABC/` in a *checked-out* test dir is wrong —
   it only exists after a run. Read the SWF's tag list for `DoABC` (72) /
   `DoABC2` (82) instead. This single mistake is what sent s11's mask_reapply
   diagnosis to a nonexistent bucket.
2. **`verify_output.py` swallows the test binary's stderr**, and `--verbose`
   does not surface it. To get a debug `fprintf(stderr, …)` out of a graphics
   test: `SWF_KEEP_BUILD_DIR=<dir> verify_output.py …`, then run
   `<dir>/test_run` directly.
3. **Canary false-positive mode 3 is easy to trip when the canary is slow and
   the edit is quick.** My first `before` leg was started before the edits and
   three of its tests compiled *after* them; it was discarded. The fix that let
   me keep iterating: capture `before` from a **pristine-at-HEAD COPY** of the
   worktree (`cp -r` the worktree, restore the four edited files from the main
   tree, verify with `diff -q`) and point `--out` at the *worktree's*
   `.render_canary` so `compare` pairs the two legs. Cost: the copy lives at a
   different path, `-I<tree>` is part of the ccache key, so the first
   pristine leg pays a **full cold ccache** (~5 min/test under load; ~6 s/test
   on the restart).

Machine was shared with seven sibling agents (load average 9–20) throughout;
every probe was run sequentially and the canary legs at `-P 2`.
