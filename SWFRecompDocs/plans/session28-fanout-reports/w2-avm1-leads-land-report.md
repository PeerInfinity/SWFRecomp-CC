## 1. Patch scope (functions touched)

**`SWFModernRuntime/src/actionmodern/action.c`**
- `actionLoadedMovieDeliveredThisTick`, new static `actionNoteLoadedMovieDelivered`, and its one call in
  `actionFirePendingDirectLoadsImpl`. The 16-slot ring becomes an epoch-keyed growable list (from w1, unchanged).
- `avm1QueueFormDataEvent` and `avm1FireFormDataEvents`. The queue is growable (w1), and now holds
  `PendingFormData {mc, gen}` entries:
  - `g_form_data_gen` advances once per drain; the drain runs once per tick, from `processLoadVarsLoads` in both frame loops.
  - A drain fires only the entries queued before it began, so a load issued in frame N's script fires after frame
    N+1's script.
  - Entries queued from **inside** the drain (an `onData` that issues another loadVariables, as in gnash MovieClip-v6's
    handshake) get `gen = 0` and stay immediate. The re-entrant chain therefore still completes within the frame
    budget, exactly as before.
  - Not-yet-due entries stay queued in order. Holding a `MovieClip*` across a tick is safe: MovieClips are never freed,
    only tombstoned (action.c ~34949), and the drain's existing liveness predicate covers that.
- `aq_dispatch_timeline_unload` (the drain side of `actionFireOnUnload`). It switches context to the dying clip only
  for a SWF5 handler (`func->swf_version < 6`, falling back to `g_swf_version`), and passes `this_mc = pu->mc` to
  `invokeUnloadHandler` (`INV_THIS_STACK | INV_MC_THIS_NULL_PTR | INV_EVENT_THIS_MC`). This is the same pairing
  `aq_dispatch_unload` uses. `actionFireOnUnload` itself is unchanged.

**`SWFModernRuntime/src/actionmodern/sprite_frame_scripts.c`**: `actionQueuePendingSpriteScript` is growable (w1, unchanged).

**`SWFModernRuntime/src/libswf/tag.c`** (NO_GRAPHICS‖OFFSCREEN arm): `queue_pending_finalize_mc` and `run_pending_finalize`
(w1, unchanged).
- The table is growable.
- The walk takes ownership of the table first. This also fixes a latent bug: an enqueue during the walk used to
  overwrite not-yet-walked entries `[0..k)`.

No other sibling-owned function is touched.

## 2. Mechanism of 1b (why our onData came before `frame 2`)

`avm1QueueFormDataEvent` is called synchronously from the loadVariables opcode or method (the parse already happened,
since loads are registry reads). The drain sits in `processLoadVarsLoads`, which runs at the end of the **same** tick
(swf.c ~1495, swf_core.c ~1585). So `onData` printed before `frame 2`. That is Ruffle's runner order: it polls the
executor and queues `onData` right after the frame (`core/src/loader.rs:1041`).

FP32 prints `frame 2` first and all 20 `onData` lines before `frame 3`. It is the same one-tick-later rule FP32 showed
for direct `loadMovie` delivery in s27 (`regression/avm1_loaded_timeline_holder` and friends), so I treated it as a
general rule rather than a fixture-only special case.

**Not changed (priced):**
- The *variables themselves* still land synchronously, at loadVariables time. Flash probably sets them at
  delivery too, so `m0.a` is likely `undefined` in frame 2's script in Flash; this fixture does not observe it.
- `LoadVars.load` / `sendAndLoad` (`g_pending_lv_loads`) still fire in the same tick.

Both are listed as Flash requests below; no corpus row distinguishes either.

## 5. Refutations / premise checks

- "Our onData fires before frame 2's script": confirmed. Mechanism: the same-tick drain in `processLoadVarsLoads`.
  The worry that one tick of delay would starve gnash MovieClip-v6 (handshake in the LAST frame, per the drain's own
  comment) is handled by keeping in-drain re-queues immediate. MovieClip-v5..v8 are measured diff-identical.
- "Fix it in `actionFireOnUnload`": the enqueue side was fine. The bug is in the drain (`aq_dispatch_timeline_unload`),
  which unconditionally did `actionSetCurrentContext(pu->mc)`. The sibling `aq_dispatch_unload` (removeMovieClip path)
  had already been fixed to the closure rule in normalization pass (b). The timeline-RemoveObject path was missed.
- The w1 queue prototype was verified byte-for-byte against FP32 on 2 of its 3 fixtures, as the brief stated.
