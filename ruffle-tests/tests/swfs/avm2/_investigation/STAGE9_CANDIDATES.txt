# AVM2 Stage 9 candidate list — minimal render path (Bitmap blit + solid fills)
#
# Generated at session start (2026-07-12) by cross-referencing the avm2 tests
# carrying an [image_comparisons] section in test.toml against the graphics-mode
# results. These tests currently "pass" in no-graphics only because they trace
# nothing (output.txt is empty / trivial); they become observable only under
# --mode=graphics, where the offscreen framebuffer is captured to PNG and
# compared to output.expected.png with per-channel tolerance/max_outliers.
#
# The full [image_comparisons] set is 109 tests. Most need machinery far beyond
# a minimal render path (Stage3D/AGAL, PixelBender/Shader, filters, gradients,
# real shape tessellation, masks, Loader/JPEG-XR). Stage 9's scope is the
# **Bitmap/BitmapData blit family** (+ trivial solid-color Graphics fills), so
# this list is the blit-gradeable subset plus the explicitly-deferred siblings
# for triage bookkeeping.
#
# Exit: a strong majority of TIER 1 + TIER 2 passing; image tests triaged;
# zero pass->fail regressions in EITHER mode.
#
# LOCAL RESULTS (2026-07-12, --mode=graphics):
#   TIER 1: 8/9 PASS. Passing: bitmapdata_fillrect, _clone, _copychannel,
#     _copypixels, _colortransform, _embedded, _sync, _pixeldissolve_image.
#     Miss: bitmap_subclass_properties — NOT a render bug: its `Test.TestBitmap`
#     nested-subclass construction aborts the script at trace line 2 (a
#     Stage-7-era embedded-subclass gap); fails identically in no-graphics, so
#     it is a PRE-EXISTING miss, not a Stage-9 regression.
#   TIER 2 (BitmapData.draw): the CPU fast path (BitmapData/Bitmap source +
#     normal blend + identity 2x2 matrix) landed and is correct, but every
#     TIER-2 candidate draws a DisplayObject that is NOT a Bitmap — a TextField
#     (draw_cpu_overwrite_gpu, draw) or a MovieClip/Sprite-with-graphics
#     (draw_self_via_graphic, draw, opaque) — which needs the offscreen GPU
#     render pipeline + a shape/text rasterizer (out of Stage 9 scope). Those
#     skip (honest no-op) exactly as before, so no regression. draw_alpha_erase:
#     its BitmapData-source no-op lines are now correct, but the Bitmap-source
#     alpha/erase lines need the GPU group-blend pipeline -> still a miss.
#   => The pure-blit bitmap family (the Stage-9 target) is 8/9. draw()/shape
#      rasterization is the natural Stage-10+ follow-up.
