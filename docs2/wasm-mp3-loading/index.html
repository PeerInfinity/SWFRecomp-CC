WASM MP3 Loading Demo

Back to Index

Three ways to get an MP3 from "somewhere" into a WASM runtime, all decoded by the same C-side minimp3 call and played via WebAudio. The C source is identical in all three cases (fopen + decode + hand-off); the difference is purely in how the bytes get into memory.

Playback:
1. Bundled via --preload-file

The entire assets/ directory was packed into the build's .data sidecar at compile time (emcc --preload-file assets@/assets). From C, each file is just a regular path on Emscripten's MEMFS — the dropdown picks which one to fopen. This is the pattern for "ship a set of levels / music tracks with the game."

2. User-supplied file (file picker / drag-drop)

Pick a local MP3. JS reads the bytes and writes them to /uploads/<name>.mp3 via FS.writeFile; C then opens that path with fopen, indistinguishable from the bundled case. This is the "user installs a mod from disk" pattern. For persistence across reloads, mount IDBFS at /uploads and call FS.syncfs(false) after writing.

3. Remote URL (emscripten_fetch)

C-side async HTTP GET, no MEMFS round-trip. The default URL below points at the same bundled MP3 served by your local HTTP server. Replace it with a CORS-friendly absolute URL to simulate "mod hosted on GitHub Pages / a CDN".
